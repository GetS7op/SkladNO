## Решения
- D-01. Новый проект называется SkladNO. [П]
- D-02. Проект пишется с нуля. Код старых проектов не переносится, только правила и стиль. [П]
- D-03. Единый вид реестра: строка «Поиск», кнопка «~option», фильтры, таблица. [П]
- D-04. Колонки таблиц делятся на «Оффлайн ф-кции» и «Онлайн ф-кции». [П]
- D-05. «Состояние» поставки: 4 значения. Признак «таможенные» только у «Прямо с завода». [П]
- D-06. Адрес места задается формулой `MXCXSXP` (M=модуль, C=контейнер, S=стеллаж, P=полка, X=разделитель). [П]
- D-07. «Парк» и «Мастерская» являются складами. «Назначение» поставки выбирает склад и диапазон Index. [П]
- D-08. Значения «Состояния» поставки: «Прямо с завода» (таможенные), «Немного поношенные», «После полевых испытаний», «Закаленные в боях» (три последних — не таможенные, зависят от внешнего состояния устройств). [П]
- D-09. Ошибки при подтверждении и закрытии поставки — предупреждения: этап не блокируется, замечания показываются и записываются в журнал. [П]
- D-10. Пулы ведутся отдельным справочником: наименование и стратум-ссылки. «Онлайн» и «XP» — в будущей итерации: решается, писать свой сканер с API или брать API действующего сканера ЦОД. [П]
- D-11. Данные skladno-mf-old не переносятся: справочники и устройства заполняются вручную или загружаются в будущем через шаблоны поставок (загрузка данных устройств: INDEX, MAC, серийный номер). [П]
- D-12. Склады — справочник: имя и маска INDEX (7 знаков: префикс из цифр склада + X на месте номера). Новый склад добавляет администратор; диапазоны складов не пересекаются; маска после создания не меняется. «Парк» — `0XXXXXX` (0000001–0999999), «Мастерская» — `9XXXXXX`. «Расположение» модуля — склад из справочника (отдельное текстовое расположение убрано). [П]

## Глоссарий
| Термин | Определение |
|---|---|
| Index | Идентификатор устройства, 7 знаков, не меняется. [П] |
| XP | Производительность (хешрейт) устройства. [П] |
| Склады | Раздел «Парк/Мастерская (Склады)». [П] |
| Модуль | Верхний уровень адреса. Имеет порядковый номер, физическое расположение и набор экземпляров контейнеров. [П] |
| Контейнер | Физический объект (тип/шаблон) с характеристиками: мощность, количество стеллажей, полок, описание. Порядковый номер экземпляра задается при формировании модуля. [П] |
| Место | Единица вместимости («Свободно мест», «Занято мест»). Учет ведется по полке как счетчик. [П] |
| Тамагочи (ТСД) | Терминал сбора данных для сканирования штрихкодов полок и наклеек INDEX в оффлайн-режиме. [П] |
| Формула адреса | `MXCXSXP`, где M, C, S, P — числовые порядковые номера. Разделитель задается в настройках (по умолчанию латинская «X»). [П] |
| Мощность контейнера | Числовое поле в кВт. Является жестким ограничением при размещении устройств. [П] |

## Карточки функций

### F-01. Реестр устройств и характеристик
**Приоритет:** P1. **Источник:** новая. **Состояние:** макет v1.
**Назначение:** справочник связок «Производитель + Модель» и их технических характеристик. [П]
**Данные:** Производитель (список/INPUT, обязательно), Модель (INPUT/список, обязательно), Хешрейт (число, Th/s), Энергопотребление (число, Вт), Размеры (текст, мм, автоформатирование в «AxBxC»), Вес (текст/диапазон, кг). [П]
**Правила:**
- R-01. Удаление производителя и модели запрещено, доступно архивирование. [П]
- R-02. Поле «Размеры» принимает числа и разделители, система форматирует их в вид «AxBxC». [П]
- R-03. Уникальность: комбинация «Производитель + Модель» уникальна. [П]
**Приёмка:** Дано: пользователь вводит габариты "400 195 290". Когда: сохраняет форму. Тогда: система сохраняет и отображает "400x195x290". [П]

### F-02. Клиенты
**Приоритет:** P1. **Источник:** новая. **Состояние:** макет v1.
**Назначение:** справочник клиентов для сводки по оборудованию и привязки поставок. [П]
**Данные:** Наименование (уникально, ≥3 символов, обязательно), Заметка (необязательно). [П]
**Правила:** Удаление и архивирование запрещено. Разрешено редактирование. Подсчет «Поставок» и «Устройств» включает все поставки клиента независимо от состояния. [П]
**Результаты:** Выгрузка (экспорт) списка устройств клиента. [П]

### F-03. Поставки устройств
**Приоритет:** P1. **Источник:** новая, правила из mf-old. **Состояние:** макет v1.
**Назначение:** учёт поступления партии устройств, присвоение Index и привязка к местам размещения. [П]
**Шаги:** 1. Создание поставки (шапка + строки). 2. Физическое размещение и наклейки. 3. Прием поставки (сканирование ТСД: штрихкод полки + INDEX). 4. Подтверждение и закрытие (Старший СА). [П]
**Данные (Шапка):** Клиент, Группа устройств, Наименование (ПУ-ГОД-НОМЕР), Дата, Документ-основание (текст+дата, необязательно), Файлы (jpg, pdf на SMB), Состояние (4 значения), Назначение (Парк/Мастерская). [П]
**Состояния:** Создание → Прием поставки → Подтверждение поставки → Закрытие поставки. [П]
**Правила:**
- R-01. Index генерируется по назначению: «Парк» от 0000001, «Мастерская» от 9000000. [П]
- R-02. Изменение количества устройств и их типа после создания запрещено. [П]
- R-03. Функция ручной привязки к диапазону Index («Начало», «Конец») полностью удалена. [П]
**Для Claude Code:** [CC] проверить `deliveries.rs` и миграции в mf-old (транзакции, нумерация, запрет удаления).

### F-04. Вайтлист пулов (стратумы)
**Приоритет:** P2. **Источник:** новая. **Состояние:** макет v1.
**Назначение:** хранение пулов и стратум-линков для шаблонов настроек. [П]
**Данные:** Наименование пула, Стратум-линк 1-3 (мин. 1 обязательно), Разрешение (BOOLEAN, по умолчанию Да). [П]
**Правила:** Удаление запрещено, доступно архивирование. Валидация формата ссылки не требуется. [П]

### F-05. Вайтлист воркеров
**Приоритет:** P2. **Источник:** новая. **Состояние:** макет v1.
**Назначение:** хранение данных по воркерам для онлайн-проверки и агрегации метрик. [П]
**Данные:** Пул, Воркер (уникален в рамках пула), Группа (создание на месте), Вотчерлинк (URL, необязательно). [П]
**Правила:** Агрегация «Онлайн» и «XP» для группы рассчитывается как сумма показателей активных воркеров группы. [П]

### F-06. Склады (Парк/Мастерская)
**Приоритет:** P2. **Источник:** новая. **Состояние:** макет v1 (пустая рамка).
**Назначение:** отображение сводных данных о размещении и вместимости по двум складам на основе данных от Карты местоположений (F-09). Активные действия по перемещению не требуются. [П]

### F-07. Контейнеры
**Приоритет:** P2. **Источник:** новая. **Состояние:** макет v1.
**Назначение:** описание типа (шаблона) контейнера и его характеристик. [П]
**Данные:** Наименование, Сокращение, Мощность контейнера (кВт, жесткое ограничение), Кол-во стеллажей, Габариты полки X.Y.Z (мм), Кол-во полок, Кол-во устройств на полку. [П]
**Правила:** Кнопки «Добавить стеллаж/полку» добавляют блоки полей. Изменение параметров допустимо, но система блокирует операцию ошибкой при конфликте с размещенными устройствами. Удаление и импорт не предусмотрены. [П]

### F-08. Модули
**Приоритет:** P2. **Источник:** новая. **Состояние:** макет v1.
**Назначение:** описание модуля как набора экземпляров контейнеров с расположением. [П]
**Данные:** Порядковый номер модуля, Расположение модуля (справочник с возможностью создания нового), Тип контейнера (из F-07), Порядковый номер контейнера (экземпляр). [П]
**Правила:** Форма называется «Новый модуль», реестр — «Реестр модулей». Заголовок «Ячейки» не используется. Удаление и импорт не предусмотрены. [П]

### F-09. Карта местоположений (формула MXCXSXP)
**Приоритет:** P2. **Источник:** новая. **Состояние:** макет v1.
**Назначение:** построение карты местоположений по формуле с разделителем `X`. [П]
**Правила:** Адрес формируется из числовых порядковых номеров компонентов (M, C, S, P). Размещение устройства осуществляется путем сканирования штрихкода полки и INDEX устройства ТСД. Занятость полки учитывается как общий счетчик. [П]
**Для Claude Code:** [CC] проверить `locations.py`, `site_config.py` в mf-old (устойчивые ID мест).

## Сквозные темы
- **Пользователи и роли:** Доступ по ссылке-приглашению (роль + срок действия или бессрочно). Форма регистрации: Фамилия, Имя, Отчество, Логин, Пароль, Почта, Telegram Username (необязательно). [П]
- **Журнал действий:** Фиксация: «Когда, кто и что сделал». Для устройств дополнительно: «Когда, что изменилось, старое значение, новое значение». [П]
- **Работа без связи:** Полная поддержка оффлайн-режима для ТСД. При конфликте синхронизации данные ТСД отклоняются с ошибкой для ручного разбора. [П]
- **Импорт и экспорт:** Форматы: CSV, XLSX, MD (со статистикой). [П]
- **Внешний вид:** Стандартная светлая тема. [П]
