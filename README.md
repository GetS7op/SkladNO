# SkladNO

Учёт, мониторинг и управление майнинг-фермой. Пишется с нуля по [docs/SPEC.md](docs/SPEC.md);
skladno-pc-old и skladno-mf-old (папка `SNO-Old`) — только референсы правил и стиля.

## Что готово (этап 1, функции P1)

| ID | Функция | Что работает |
|---|---|---|
| F-01 | Устройства | Реестр «Производитель + Модель», уникальность без учёта регистра, размеры → `AxBxC`, архив вместо удаления |
| F-02 | Клиенты | Справочник (≥ 3 символов, уникально), счётчики поставок и устройств, выгрузка устройств клиента в CSV |
| F-03 | Поставки | Шапка + строки, номер `ПУ-ГОД-НОМЕР`, Index по назначению (Парк с 0000001, Мастерская с 9000000), UUID v5 устройств, 4 этапа, состав после создания заморожен |
| — | Журнал | Когда, кто и что сделал; для изменений — старое и новое значение |

Разделы F-04…F-09 видны в меню как «Следующий этап».

## Стек

Rust 2024 (Axum 0.8, SQLx 0.8, PostgreSQL 18) — модульный монолит: `crates/core` и модули
`crates/modules/{catalog,clients,deliveries}`, сборка в `crates/app`. Frontend: React 19, TypeScript,
Vite, TanStack Query.

## Запуск

```bash
scripts/configure.sh            # создаёт .env со случайным паролем БД
docker compose up -d --wait postgres
scripts/app.sh                  # API на 127.0.0.1:8090, миграции применяются сами
npm --prefix frontend install
npm --prefix frontend run dev   # интерфейс на http://localhost:5174
```

Если выполнить `npm --prefix frontend run build`, `scripts/app.sh` раздаёт интерфейс сам на порту 8090.

## Проверки

```bash
cargo test --workspace
npm --prefix frontend run typecheck
```

## Ограничения этапа 1

- Входа и ролей пока нет: все действия в журнале записываются от имени «система».
- Файлы документа-основания (jpg/pdf на SMB), ТСД и офлайн-синхронизация — следующий этап.
- «Состояние устройств» (4 значения, признак «таможенные») и критерии «критических ошибок» при закрытии
  поставки в SPEC не определены — не реализованы до ответа владельца.
