# SkladNO

Учёт, размещение и мониторинг оборудования майнинг-фермы: поставки устройств с присвоением Index,
карта мест (модуль → контейнер → стеллаж → полка), приём сканированием, склады, вайтлисты пулов
и воркеров, журнал действий.

Пишется с нуля по [docs/SPEC.md](docs/SPEC.md); skladno-pc-old и skladno-mf-old — только референсы
правил и стиля.

## Установка на сервер

Всё работает в Docker: два контейнера — PostgreSQL и само приложение (backend и интерфейс на одном
порту). Rust и Node.js на сервер ставить не нужно — сборка идёт внутри Docker.

> **Важно.** Сразу после запуска (шаг 5) откройте SkladNO и создайте администратора: пока
> пользователей нет, форму первого запуска может заполнить любой, кто откроет адрес. Открывайте
> SkladNO только во внутренней сети фермы, не пробрасывайте порт в интернет — соединение идёт по
> HTTP без шифрования.

### Что нужно

- Linux-сервер (Ubuntu 22.04+/Debian 12+ или любой с Docker), 2 ГБ ОЗУ, 10 ГБ диска.
- Доступ в интернет на время установки (скачать образы и зависимости).
- Права `sudo`.

### 1. Установить Docker и git

Ubuntu / Debian:

```bash
sudo apt update
sudo apt install -y git curl
curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker "$USER"
```

После `usermod` **выйдите из системы и зайдите снова** (или перезагрузите сервер), иначе Docker
будет отвечать «permission denied». Проверка:

```bash
docker run --rm hello-world
```

Docker должен запускаться сам после перезагрузки сервера:

```bash
sudo systemctl enable --now docker
```

### 2. Скачать SkladNO

```bash
sudo mkdir -p /opt/skladno
sudo chown "$USER": /opt/skladno
git clone https://github.com/GetS7op/SkladNO.git /opt/skladno
cd /opt/skladno
```

### 3. Создать настройки

```bash
scripts/configure.sh
```

Скрипт создаёт файл `.env` со случайным паролем базы данных. **Сохраните копию `.env`** в надёжном
месте: в git он не попадает, а без него приложение не подключится к уже существующей базе после
переустановки.

Если порт 8090 на сервере занят, допишите в `.env` строку `APP_PORT=8095` (любой свободный).

### 4. Собрать и запустить

```bash
docker compose up -d --build
```

Первая сборка занимает 5–15 минут (компилируется Rust). Следующие запуски — секунды. Проверка:

```bash
docker compose ps
curl http://127.0.0.1:8090/api/v1/health   # приложение напрямую, на самом сервере
```

`docker compose ps` должен показать `postgres` в состоянии `healthy` и `app` в состоянии `Up`,
а `curl` — ответить `ok`. Таблицы базы создаются автоматически при первом запуске.

### 5. HTTPS и открытие в браузере

SkladNO открывается по HTTPS через Caddy со своим центром сертификации (ЦС). Сертификат выпускается
на IP из `SKLADNO_IP` в `.env` (его ставит `scripts/configure.sh`, проверьте его через `ip -4 addr`).
Нужны свободные порты 80 и 443 (другие можно задать через `HTTP_PORT`/`HTTPS_PORT` в `.env`).

На каждом ТСД и компьютере **один раз** установите корневой сертификат:

1. Откройте `http://<IP-сервера>/ca.crt`, скачается `skladno-ca.crt`.
2. Android/ТСД: Настройки → Безопасность → Шифрование и учётные данные → Установить сертификат →
   Сертификат ЦС → выберите файл.
   Windows: двойной клик по файлу → Установить → Локальный компьютер → «Доверенные корневые центры
   сертификации».
3. Откройте `https://<IP-сервера>` — предупреждения быть не должно.

Отпечаток сертификата для сверки: `scripts/https-ca.sh`. Том `caddy_data` хранит ключи ЦС —
при его удалении сертификат придётся ставить на устройства заново.

#### Адрес по имени вместо IP (например `https://apatity.skladno.org`)

1. Впишите имя в `.env` (можно несколько через пробел) и перезапустите `docker compose up -d`:

   ```bash
   SKLADNO_NAMES=apatity.skladno.org
   ```

   Caddy выпустит сертификат и на это имя; по IP SkladNO тоже продолжит открываться.
2. Имя должно указывать на IP сервера в сети фермы — один из вариантов:
   - **Свой домен** (например `skladno.org`): у регистратора/в DNS добавьте запись
     `A apatity → 192.168.1.10` (внутренний IP сервера). Работает на всех устройствах сразу.
     Некоторые роутеры блокируют такие ответы («защита от DNS rebinding») — тогда добавьте
     исключение для домена в настройках роутера.
   - **Без своего домена**: статическая DNS-запись на роутере фермы (в Keenetic, MikroTik, OpenWrt
     это «DNS-записи / Static DNS»). Не берите чужой публичный домен — для внутренних имён есть
     зарезервированная зона `.home.arpa`, например `apatity.skladno.home.arpa`.
3. Корневой сертификат на устройства ставится так же, как выше: он один для IP и для имён.

Обойтись без установки сертификата на устройства можно только с **собственным** доменом и
сертификатом Let's Encrypt, полученным через DNS провайдера (Cloudflare и т. п.) — это отдельная
настройка, её можно добавить, когда домен будет.

Если файрвол `ufw` включён, откройте порты для внутренней сети (пример для `192.168.1.0/24`):

```bash
sudo ufw allow from 192.168.1.0/24 to any port 80,443 proto tcp
```

Контейнеры перезапускаются сами после сбоя или перезагрузки сервера (`restart: unless-stopped`).

### 6. Администратор и сотрудники

1. При первом открытии SkladNO показывает форму «Первый запуск» — заполните её, это учётная запись
   администратора.
2. Сотрудников приглашайте ссылками: **Настройки → Пользователи → Приглашения → Новое приглашение**, выберите
   роль и срок действия (1/7/30 дней или бессрочно). Ссылка показывается один раз и работает для
   одной регистрации — отправьте её сотруднику, он заполнит ФИО, логин, пароль, почту и Telegram.
3. Роли:

| Роль | Что может |
|---|---|
| СА | Всё видеть, создавать поставки, переводить их на «Приём поставки», размещать устройства сканированием |
| Старший СА | + справочники (устройства, клиенты, контейнеры, модули, пулы, воркеры), подтверждение и закрытие поставок |
| Администратор | + пользователи: приглашения, смена ролей, отключение, сброс пароля; склады и разделитель адреса |

Администратор может посмотреть интерфейс глазами другой роли: внизу меню **Вид: СА / Старший СА**.
Меню и кнопки становятся как у этой роли, сверху висит плашка с кнопкой «Вернуть вид администратора».
Это только вид: действия выполняются с правами администратора. Вид сбрасывается при закрытии вкладки.

Если сотрудник забыл пароль — **Настройки → Пользователи → сотрудник → Сбросить пароль**: SkladNO покажет
временный пароль, сотрудник входит с ним и меняет пароль в меню слева («Сменить пароль»).

После 10 неверных паролей подряд вход под этим логином закрывается на 15 минут (защита от подбора).
Сброс пароля администратором снимает блокировку сразу.
Последнего администратора отключить или понизить нельзя.

### 7. ТСД и работа без связи

Сканер штрихкодов подключается как обычная клавиатура (режим HID, с Enter после кода). На ТСД
откройте SkladNO в браузере и войдите. Если связь пропадёт:

- сканы сохраняются на устройстве («В очереди: N») и отправляются сами, когда связь вернётся;
- скан, который сервер отклонил при отправке (полка заполнена, превышена мощность, чужой склад),
  попадает в список «Отклонено при синхронизации — разберите вручную».

По HTTPS (шаг 5) SkladNO открывается на ТСД даже без связи — на устройстве, где уже был вход.

### 8. Первичное наполнение

Порядок, в котором справочники зависят друг от друга:

1. **Устройства** — модели (производитель, модель, XP, потребление, размеры). Если список моделей
   уже есть в Excel, загрузите его: **~option → Импорт из CSV / XLSX** (шапка как в выгрузке
   SkladNO; сначала «Проверить файл», затем «Импортировать»). Так же импортируются клиенты.
2. **Клиенты**.
3. **Склады** — «Парк» (маска INDEX `0XXXXXX`) и «Мастерская» (`9XXXXXX`) уже есть. Новый склад
   добавляет администратор: **Склады → Добавить склад**, имя и маска INDEX — 7 знаков, цифры склада
   и X на месте номера: `1XXXXXX` даёт INDEX 1000000–1999999, `21XXXXX` — 2100000–2199999.
   Диапазоны складов не пересекаются; маску после создания не меняют, имя — можно.
4. **Контейнеры** — шаблоны (мощность кВт, стеллажи, полки, устройств на полку).
5. **Модули** — номер, расположение (склад) и экземпляры контейнеров.
   Распечатайте и наклейте на полки штрихкоды адресов: **Карта → модуль → Наклейки полок**.
6. **Поставки** — создать поставку, выбрать склад назначения (INDEX выдаются по его маске),
   прикрепить скан или PDF документа-основания, распечатать наклейки устройств (**Устройства поставки → Наклейки**), перевести на этап «Приём поставки» и
   разместить устройства сканированием: штрихкод полки → INDEX устройства.
   MAC и серийные номера загружаются шаблоном: **Устройства поставки → Шаблон** (XLSX со списком
   INDEX), заполнить колонки «MAC» и «Серийный номер» (можно вставить из таблицы поставщика), затем
   **Загрузить MAC и серийные** → «Проверить файл» → «Загрузить». MAC принимается в любом написании,
   дубли отклоняются, пустая ячейка не стирает прежнее значение, изменения пишутся в журнал.
7. **Вайтлист пулов**, затем **вайтлист воркеров**.

Меню: **Главная** (реестр INDEX) — сверху; **Учёт** — поставки, отправки, комплектующие;
**Преднастройки** — вайтлисты пулов и воркеров; **Настройки** — склады, карта, модули, контейнеры,
устройства, клиенты, статусы, пользователи; **Система** — журнал.

**Статусы устройств** (как в mf-old) — **Настройки → Статусы**: категории (в контейнере, в мастерской,
отсутствует), статусы и матрица переходов, при первом запуске заполнены как в mf-old. Статус виден на
«Главной» (столбец и фильтр) и в карточке устройства; СА переводит устройство по матрице, Старший СА —
в любой статус (в журнале пометка «вне матрицы»).

**Отправки** — **Учёт → Отправки**: устройства уезжают к контрагенту (ремонт) или клиенту и возвращаются.
«Новая отправка»: номера через запятую или диапазоном (`0000001-0000004, 0000007`), кому, даты.
Статус ставится сам по самой поздней дате: упаковали — «Упакован», отправили — «Возврат», вернулось —
«Ремонт». Пока нет даты прибытия, упаковать устройство повторно нельзя. Клик по строке — даты и
результат ремонта, кнопка «Прибыло сегодня».

**Комплектующие** — **Учёт → Комплектующие**: позиции и типы заводит Старший СА; «Приход» —
поступление от поставщика; «Установка, снятие, списание» — по INDEX устройства (попадает в историю
устройства). Остаток = приход − установлено + снято − списано, больше остатка не установить и не
списать.

Найти любое устройство — **Главная** (реестр INDEX, как склад в mf-old): плитки «Устройств»,
«Клиентов», «Позиций устройств», «С MAC-адресом» и сводки с главной mf-old — «Ждут размещения»,
«В ремонте», «Отсутствуют на площадке» (клик включает фильтр), «Не вернулись из отправки» (ведёт в
отправки); фильтры по складу, размещению и статусу (или категории статусов) и строка поиска,
которая понимает несколько критериев сразу (через запятую, точку с запятой, пробел или перенос строки):

- число — INDEX: `5` и `0000005` одно и то же; `1-4` или `0000001-4` — диапазон;
- MAC в любом написании: `AA:BB:CC:DD:EE:FF`, `aabbccddeeff`, `AA-BB-CC-DD-EE-FF`;
- остальное — текст по модели, серийному номеру, клиенту, номеру поставки, группе устройств.

Критерии соединяются через «или»; с галочкой «Точное совпадение» — через «и». Под строкой видно, как
понят запрос, например «номера 0000001–0000003; MAC CE:0B:0C:00:28:43». Все найденные устройства
показываются в одной таблице: сортировка по клику на заголовок, **Столбцы** — какие показывать
(выбор запоминается в браузере), **Выгрузить CSV** — найденное с видимыми столбцами. Запрос и фильтры
сохраняются в адресе страницы. Клик по строке открывает карточку устройства: модель, поставка, склад
и полка, история изменений, правка MAC и серийного номера (у закрытой поставки — только Старший СА).

**Настройки → Склады → Адрес места на карте** (меняет администратор): разделитель адреса полки — `X` (по умолчанию), `-`, `.`, `/` или
`_`. Адреса на карте, в реестрах и выгрузках сразу показываются с новым разделителем, новые
наклейки полок печатаются с ним же. Уже наклеенные штрихкоды с `X` сканер читает и после смены.

Наклейки печатаются из браузера (Ctrl+P) в двух раскладках: **A4, 3×7** (63,5×38,1 мм — листы
самоклеящейся бумаги) или **термопринтер 58×40 мм** (по наклейке на страницу). В окне печати
выберите масштаб 100 % и отключите поля и колонтитулы. Штрихкоды — Code128, их читает любой сканер.

### 9. Файлы документов и SMB-папка

Прикреплённые к поставкам файлы (JPG, PNG, PDF до 25 МБ) хранятся в папке по номерам поставок:
`ПУ-2026-0001/…`. По умолчанию это том Docker `files`. Чтобы файлы лежали в сетевой (SMB) папке,
смонтируйте её на сервере и укажите путь в `.env`:

```bash
sudo apt install -y cifs-utils
sudo mkdir -p /mnt/skladno-docs
# /etc/fstab (одной строкой; логин и пароль шары — в файле /root/.smb-skladno, права 600):
# //192.168.1.20/docs/skladno /mnt/skladno-docs cifs credentials=/root/.smb-skladno,uid=10001,gid=10001,iocharset=utf8,_netdev 0 0
sudo mount -a
echo 'FILES_PATH=/mnt/skladno-docs' >> .env
docker compose up -d
```

`uid=10001` — пользователь, от которого работает SkladNO в контейнере: без него в папку нельзя
записать. Удалять прикреплённые файлы из SkladNO нельзя, как и остальные записи учёта.

## Обновление

```bash
cd /opt/skladno
scripts/backup.sh                 # на всякий случай — копия перед обновлением
git pull
docker compose up -d --build
```

Изменения базы (миграции) применяются автоматически при старте приложения.

### Резервные копии

Ручная копия:

```bash
scripts/backup.sh
```

Копия БД сохраняется в `/opt/skladno/backups/skladno-ГГГГ-ММ-ДД_ЧЧММ.sql.gz`, файлы документов —
в `skladno-files-ГГГГ-ММ-ДД_ЧЧММ.tar.gz` рядом; хранятся последние 30 копий каждого вида.
Автоматически каждую ночь в 03:00 — добавьте строку через `crontab -e`:

```cron
0 3 * * * /opt/skladno/scripts/backup.sh >> /opt/skladno/backups/backup.log 2>&1
```

Папку `backups` стоит регулярно копировать на другой диск или компьютер.

Восстановление (текущие данные будут заменены, скрипт попросит подтверждение):

```bash
scripts/restore.sh backups/skladno-2026-11-02_0300.sql.gz
```

Файлы документов восстанавливаются распаковкой копии в папку хранения:

```bash
docker compose exec -T app tar -xz -C /srv/skladno < backups/skladno-files-2026-11-02_0300.tar.gz
```

### Обслуживание

| Задача | Команда |
|---|---|
| Состояние контейнеров | `docker compose ps` |
| Логи приложения | `docker compose logs -f app` |
| Логи базы | `docker compose logs -f postgres` |
| Перезапустить приложение | `docker compose restart app` |
| Остановить всё | `docker compose down` (данные сохраняются) |
| Запустить снова | `docker compose up -d` |

`docker compose down -v` **удаляет базу данных** — не используйте без свежей копии.

### Если что-то не работает

| Признак | Что делать |
|---|---|
| `permission denied ... docker.sock` | Пользователь не в группе `docker` или не перезашёл после `usermod` |
| `Запустите scripts/configure.sh` | Нет файла `.env` — выполните шаг 3 |
| `port is already allocated` | Порт занят — задайте `APP_PORT` в `.env` |
| `app` постоянно перезапускается | `docker compose logs app` — обычно база ещё не поднялась или неверный пароль в `.env` |
| Страница не открывается с других компьютеров | Файрвол — см. шаг 5; проверьте IP через `hostname -I` |

## Что готово

| ID | Функция | Что работает |
|---|---|---|
| F-01 | Устройства | Реестр «Производитель + Модель», уникальность без учёта регистра, размеры → `AxBxC`, архив вместо удаления |
| F-02 | Клиенты | Справочник (≥ 3 символов, уникально), счётчики поставок и устройств, выгрузка устройств клиента в CSV |

### Допущения [Д] — подтвердить у владельца

- Роли: СА, Старший СА, Администратор (в SPEC упомянут только «Старший СА»); права — в таблице
  раздела «Администратор и сотрудники». Приглашение одноразовое; пароль — от 8 символов.

- «Расположение» модуля — склад из справочника: так склады связаны с картой, а устройство можно
  разместить только на полку своего склада.
- Размещать сканированием можно только на этапе поставки «Приём поставки»; повторный скан другой
  полки переносит устройство (в журнал пишется старый и новый адрес).
- В контейнере у всех стеллажей одинаковое число полок.
- Мощность контейнера сравнивается с суммой «Энергопотребления» размещённых моделей; модели без
  потребления считаются как 0 Вт.
- Сканер может вводить кириллическую «Х» вместо латинской X — адрес всё равно распознаётся.

## Разработка

Стек: Rust 2024 (Axum 0.8, SQLx 0.8, PostgreSQL 18) — модульный монолит: `crates/core` и модули
`crates/modules/{catalog,clients,deliveries,identity,locations,reports,whitelists}`, сборка в
`crates/app`. Миграции — `migrations/`.

Frontend (React 19, TypeScript, Vite, TanStack Query, zod) устроен как в skladno-pc-old:

```text
frontend/src/
  main.tsx, App.tsx, styles.css      точка входа и общие стили
  core/
    api/       client.ts (запросы, ApiError, событие 401), queryClient.ts (политика повторов)
    auth/      AuthProvider, context (useAuth, useMe, useCan), ProtectedRoute, PublicOnlyRoute
    layout/    AppShell (меню), WorkspaceLayout (<Outlet>), UserMenu, OfflineBanner
    router/    index.tsx (дерево маршрутов, ленивые страницы), routes.ts (меню и права)
    ui/        Registry, Modal/Field/Segmented, format, useDebounced
    domain.ts  общие перечисления: склад, этап, состояние, роль
  modules/<раздел>/                  те же разделы, что crates backend (+ settings)
    api.ts     zod-схемы ответов и функции запросов
    hooks.ts   фабрика ключей запросов и хуки TanStack Query
    *Page.tsx  страницы, styles.css — стили раздела
```

Тесты лежат рядом с кодом (`*.test.ts`).

```bash
scripts/configure.sh                 # .env со случайным паролем
docker compose up -d --wait postgres # только база
scripts/app.sh                       # API на 127.0.0.1:8090
npm --prefix frontend install
npm --prefix frontend run dev        # интерфейс на http://localhost:5174
```

Проверки:

```bash
cargo test --workspace
npm --prefix frontend run lint       # ESLint, без предупреждений
npm --prefix frontend run typecheck
npm --prefix frontend test           # Vitest
```

Всё это, а также `cargo fmt`/`clippy`, Prettier, сборка и приёмка на чистом стенде в Docker с HTTPS
выполняются на GitHub при каждом push в `main` (`.github/workflows/ci.yml`, вкладка **Actions**).
Перед `git pull` на сервере стоит убедиться, что последний запуск зелёный.

Критерии приёмки SPEC (F-01…F-09, роли, этапы поставки, размещение, настройки, экспорт) проверяет
`scripts/acceptance.sh` через API. Он создаёт тестовые данные и работает только на **пустом**
экземпляре — например, на отдельном стенде рядом с рабочим:

```bash
git clone https://github.com/GetS7op/SkladNO.git /tmp/skladno-test && cd /tmp/skladno-test
POSTGRES_PORT=55499 SKLADNO_IP=127.0.0.1 scripts/configure.sh
printf 'APP_PORT=18090\nHTTP_PORT=18080\nHTTPS_PORT=18443\n' >> .env
COMPOSE_PROJECT_NAME=skladno-test docker compose up -d --build --wait
scripts/acceptance.sh http://127.0.0.1:18090     # «Все проверки пройдены»
COMPOSE_PROJECT_NAME=skladno-test docker compose down -v
```
