# SkladNO

Учёт, размещение и мониторинг оборудования майнинг-фермы: поставки устройств с присвоением Index,
карта мест (модуль → контейнер → стеллаж → полка), приём сканированием, склады, вайтлисты пулов
и воркеров, журнал действий.

Пишется с нуля по [docs/SPEC.md](docs/SPEC.md); skladno-pc-old и skladno-mf-old — только референсы
правил и стиля.

## Установка на сервер

Всё работает в Docker: два контейнера — PostgreSQL и само приложение (backend и интерфейс на одном
порту). Rust и Node.js на сервер ставить не нужно — сборка идёт внутри Docker.

> **Важно.** Входа по паролю в SkladNO пока нет: любой, кто откроет адрес, может вносить изменения.
> Открывайте его только во внутренней сети фермы, не пробрасывайте порт в интернет.

### Что нужно

- Linux-сервер (Ubuntu 22.04+/Debian 12+ или любой с Docker), 2 ГБ ОЗУ, 10 ГБ диска.
- Доступ в интернет на время установки (скачать образы и зависимости).
- Права `sudo`.

### 1. Установить Docker и git

Ubuntu / Debian:

```bash
sudo apt update
sudo apt install -y git curl
curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker "$USER"
```

После `usermod` **выйдите из системы и зайдите снова** (или перезагрузите сервер), иначе Docker
будет отвечать «permission denied». Проверка:

```bash
docker run --rm hello-world
```

Docker должен запускаться сам после перезагрузки сервера:

```bash
sudo systemctl enable --now docker
```

### 2. Скачать SkladNO

```bash
sudo mkdir -p /opt/skladno
sudo chown "$USER": /opt/skladno
git clone https://github.com/GetS7op/SkladNO.git /opt/skladno
cd /opt/skladno
```

### 3. Создать настройки

```bash
scripts/configure.sh
```

Скрипт создаёт файл `.env` со случайным паролем базы данных. **Сохраните копию `.env`** в надёжном
месте: в git он не попадает, а без него приложение не подключится к уже существующей базе после
переустановки.

Если порт 8090 на сервере занят, допишите в `.env` строку `APP_PORT=8095` (любой свободный).

### 4. Собрать и запустить

```bash
docker compose up -d --build
```

Первая сборка занимает 5–15 минут (компилируется Rust). Следующие запуски — секунды. Проверка:

```bash
docker compose ps
curl http://127.0.0.1:8090/api/v1/health
```

`docker compose ps` должен показать `postgres` в состоянии `healthy` и `app` в состоянии `Up`,
а `curl` — ответить `ok`. Таблицы базы создаются автоматически при первом запуске.

### 5. Открыть в браузере

С любого компьютера во внутренней сети: `http://<IP-сервера>:8090`. IP сервера можно узнать командой
`hostname -I`.

Если не открывается, а на сервере включён файрвол `ufw`, разрешите порт только для внутренней сети
(пример для сети `192.168.1.0/24`):

```bash
sudo ufw allow from 192.168.1.0/24 to any port 8090 proto tcp
```

Контейнеры перезапускаются сами после сбоя или перезагрузки сервера (`restart: unless-stopped`).

### 6. Первичное наполнение

Порядок, в котором справочники зависят друг от друга:

1. **Устройства** — модели (производитель, модель, XP, потребление, размеры).
2. **Клиенты**.
3. **Контейнеры** — шаблоны (мощность кВт, стеллажи, полки, устройств на полку).
4. **Модули** — номер, расположение, склад (Парк/Мастерская) и экземпляры контейнеров.
   Наклейте на полки штрихкоды с адресом `МXКXСXП` (например `1X2X3X4`) — их видно на «Карте».
5. **Поставки** — создать поставку, распечатать наклейки по «CSV для наклеек», перевести на этап
   «Приём поставки» и разместить устройства сканированием: штрихкод полки → INDEX устройства.
6. **Вайтлист пулов**, затем **вайтлист воркеров**.

Сканер штрихкодов подключается как обычная клавиатура (режим HID, с Enter после кода).

## Обновление

```bash
cd /opt/skladno
scripts/backup.sh                 # на всякий случай — копия перед обновлением
git pull
docker compose up -d --build
```

Изменения базы (миграции) применяются автоматически при старте приложения.

### Резервные копии

Ручная копия:

```bash
scripts/backup.sh
```

Копия сохраняется в `/opt/skladno/backups/skladno-ГГГГ-ММ-ДД_ЧЧММ.sql.gz`, хранятся последние 30.
Автоматически каждую ночь в 03:00 — добавьте строку через `crontab -e`:

```cron
0 3 * * * /opt/skladno/scripts/backup.sh >> /opt/skladno/backups/backup.log 2>&1
```

Папку `backups` стоит регулярно копировать на другой диск или компьютер.

Восстановление (текущие данные будут заменены, скрипт попросит подтверждение):

```bash
scripts/restore.sh backups/skladno-2026-11-02_0300.sql.gz
```

### Обслуживание

| Задача | Команда |
|---|---|
| Состояние контейнеров | `docker compose ps` |
| Логи приложения | `docker compose logs -f app` |
| Логи базы | `docker compose logs -f postgres` |
| Перезапустить приложение | `docker compose restart app` |
| Остановить всё | `docker compose down` (данные сохраняются) |
| Запустить снова | `docker compose up -d` |

`docker compose down -v` **удаляет базу данных** — не используйте без свежей копии.

### Если что-то не работает

| Признак | Что делать |
|---|---|
| `permission denied ... docker.sock` | Пользователь не в группе `docker` или не перезашёл после `usermod` |
| `Запустите scripts/configure.sh` | Нет файла `.env` — выполните шаг 3 |
| `port is already allocated` | Порт занят — задайте `APP_PORT` в `.env` |
| `app` постоянно перезапускается | `docker compose logs app` — обычно база ещё не поднялась или неверный пароль в `.env` |
| Страница не открывается с других компьютеров | Файрвол — см. шаг 5; проверьте IP через `hostname -I` |

## Что готово

| ID | Функция | Что работает |
|---|---|---|
| F-01 | Устройства | Реестр «Производитель + Модель», уникальность без учёта регистра, размеры → `AxBxC`, архив вместо удаления |
| F-02 | Клиенты | Справочник (≥ 3 символов, уникально), счётчики поставок и устройств, выгрузка устройств клиента в CSV |
| F-03 | Поставки | Шапка + строки, номер `ПУ-ГОД-НОМЕР`, Index по назначению (Парк с 0000001, Мастерская с 9000000), UUID v5 устройств, 4 этапа, состав после создания заморожен; на этапе «Приём поставки» — размещение сканированием |
| F-04 | Вайтлист пулов | 1–3 стратум-линка (минимум один), «Разрешение», архив вместо удаления |
| F-05 | Вайтлист воркеров | Воркер уникален в пуле, группа создаётся на месте, вотчерлинк |
| F-06 | Склады | Сводка по Парку и Мастерской: места свободно/занято, ожидают размещения, нагрузка |
| F-07 | Контейнеры | Шаблоны: мощность (кВт), стеллажи, полки, устройств на полку; уменьшить ниже занятого нельзя — показываются затронутые Index |
| F-08 | Модули | Номер, расположение, склад, экземпляры контейнеров; занятые экземпляры, номер и склад занятого модуля не меняются |
| F-09 | Карта | Адрес `MXCXSXP`, сетка полок с занятостью и нагрузкой, приём «штрихкод полки + INDEX» с проверкой вместимости полки, мощности контейнера и склада |
| — | Журнал | Когда, кто и что сделал; для изменений и перемещений устройств — старое и новое значение |

### Допущения [Д] — подтвердить у владельца

- У модуля есть поле «Склад» (Парк/Мастерская): так склады связаны с картой, а устройство можно
  разместить только на полку своего склада.
- Размещать сканированием можно только на этапе поставки «Приём поставки»; повторный скан другой
  полки переносит устройство (в журнал пишется старый и новый адрес).
- В контейнере у всех стеллажей одинаковое число полок.
- Мощность контейнера сравнивается с суммой «Энергопотребления» размещённых моделей; модели без
  потребления считаются как 0 Вт.
- Разделитель адреса — постоянная «X» (настроек пока нет); сканер может вводить кириллическую «Х».

### Ещё не сделано

- Вход по приглашениям и роли — все действия в журнале пока от имени «система».
- Офлайн-очередь ТСД (сервер к ней готов: повторный скан идемпотентен).
- Онлайн-метрики воркеров («Онлайн», «XP») — нужен доступ к API пулов.
- Файлы документа-основания (jpg/pdf на SMB), импорт/экспорт XLSX и MD.
- «Состояние устройств» (4 значения, признак «таможенные») и «критические ошибки» при закрытии
  поставки в SPEC не определены.

## Разработка

Стек: Rust 2024 (Axum 0.8, SQLx 0.8, PostgreSQL 18) — модульный монолит: `crates/core` и модули
`crates/modules/{catalog,clients,deliveries,whitelists,locations}`, сборка в `crates/app`.
Frontend: React 19, TypeScript, Vite, TanStack Query. Миграции — `migrations/`.

```bash
scripts/configure.sh                 # .env со случайным паролем
docker compose up -d --wait postgres # только база
scripts/app.sh                       # API на 127.0.0.1:8090
npm --prefix frontend install
npm --prefix frontend run dev        # интерфейс на http://localhost:5174
```

Проверки:

```bash
cargo test --workspace
npm --prefix frontend run typecheck
```
